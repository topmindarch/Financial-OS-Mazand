# راهنمای فارسی نصب، راه‌اندازی، به‌روزرسانی و نگهداری

## ۱. پیش‌نیازها
این پروژه ربات تلگرام «مازندشت | باغدشت» برای مدیریت قیمت خرید و فروش مرکبات است. به Bot Token از BotFather، شناسه عددی یک مدیر، Docker و Docker Compose (یا Python 3.11+ و PostgreSQL)، و دسترسی شبکه سرور به Telegram Bot API نیاز دارید.

این مخزن کد و پیکربندی را فراهم می‌کند؛ ربات تا وقتی توکن واقعی، دیتابیس و میزبان اجرا تنظیم نشده باشند آنلاین نیست. توکن و رمز دیتابیس را در GitHub، Slack یا فایل قابل‌اشتراک قرار ندهید.

## ۲. دریافت پروژه
در GitHub وارد مخزن topmindarch/Financial-OS-Mazand شوید و از Code → Download ZIP دریافت کنید؛ یا اجرا کنید:

    git clone https://github.com/topmindarch/Financial-OS-Mazand.git
    cd Financial-OS-Mazand

پس از انتشار به‌روزرسانی جدید می‌توانید با git pull نسخه جدید را دریافت کنید.

## ۳. تنظیمات محرمانه
فایل نمونه را کپی کنید:

Linux/macOS:
    cp .env.example .env
    nano .env

Windows PowerShell:
    Copy-Item .env.example .env
    notepad .env

مقدارهای زیر را در .env وارد کنید:
- BOT_TOKEN: توکن واقعی ربات.
- ADMIN_TELEGRAM_IDS: شناسه عددی مدیرها؛ برای چند مدیر از ویرگول استفاده کنید.
- DATABASE_URL: نشانی اتصال PostgreSQL محیط جاری.
- LOG_LEVEL: معمولاً INFO.

در Docker Compose مقدار POSTGRES_PASSWORD در docker-compose.yml و رمز متناظر در DATABASE_URL باید یکسان و قوی باشند. فایل واقعی .env نباید commit شود. پورت پایگاه داده فقط روی loopback منتشر شده است؛ آن را عمومی نکنید.

## ۴. اجرای محلی با Docker Compose
از ریشه مخزن اجرا کنید:

    docker compose up --build -d
    docker compose ps
    docker compose logs -f bot

برای مشاهده گزارش دیتابیس:
    docker compose logs -f db

توقف بدون حذف داده:
    docker compose down

هشدار: docker compose down -v حجم داده دیتابیس را هم حذف می‌کند؛ از آن استفاده نکنید مگر نسخه پشتیبان داشته باشید و حذف اطلاعات را عمداً بخواهید.

فایل app/schema.sql فقط هنگام اولین ساخته‌شدن volume دیتابیس به طور خودکار اعمال می‌شود. اگر volume قبلاً ایجاد شده باشد، ویرایش این فایل آن را دوباره اجرا نمی‌کند. برای دیتابیس موجود، migration کنترل‌شده اجرا کنید؛ volume را حذف نکنید.

## ۵. راه‌اندازی Supabase
در مخزن، migration اولیه SQL آماده است؛ اتصال به دیتابیس زنده زمانی کامل می‌شود که پروژه Supabase انتخاب/ساخته و تنظیمات اتصال دریافت شده باشد.

۱. در Supabase پروژه‌ای موجود انتخاب یا پروژه مجاز جدید بسازید.
۲. از تنظیمات اتصال، URI امن PostgreSQL/Pooler را برای محیط سروری دریافت کنید.
۳. فایل supabase/migrations/202610230001_init.sql را در SQL Editor پروژه اجرا کنید یا با Supabase CLI مطابق گردش‌کار migration آن را اعمال کنید.
۴. در محیط امن ربات، DATABASE_URL را روی URI واقعی بگذارید. رشته اتصال را در کد کلاینت یا مخزن عمومی قرار ندهید.
۵. BOT_TOKEN و ADMIN_TELEGRAM_IDS را در محیط اجرا تنظیم کنید.
۶. سرویس ربات را بالا آورده و لاگ‌ها و اتصال پایگاه داده را بررسی کنید.

این migration روی جدول‌های داده RLS را فعال و دسترسی مستقیم نقش‌های anon و authenticated را می‌بندد. ربات فعلی از اتصال سروری PostgreSQL استفاده می‌کند، نه از Data API عمومی. اگر معماری به Supabase REST API تغییر کند، سیاست‌های RLS و مجوزها باید جداگانه طراحی و تست شوند.

## ۶. ورود مدیر و مدیریت حساب‌ها
مدیر شناسه عددی خود را در ADMIN_TELEGRAM_IDS ثبت کند، سپس ربات را باز کرده و /start و /admin_help را اجرا کند. کاربران جدید با /start ثبت می‌شوند و تا تأیید مدیریت قیمت نمی‌بینند.

فرمان‌ها:
- /pending — فهرست درخواست‌های در انتظار و دکمه تأیید/رد.
- /groups — شناسه و نام گروه‌ها (فقط برای مدیر).
- /products — فهرست محصولات.
- /grant ID buy — مجوز خرید.
- /grant ID sell — مجوز فروش.
- /grant ID both — هر دو مجوز.
- /grant ID none — حذف هر دو مجوز.
- /assign ID buy GROUP_ID — تخصیص گروه خرید.
- /assign ID sell GROUP_ID — تخصیص گروه فروش.
- /settype ID regular یا /settype ID special — نوع حساب.

نوع حساب regular/special به‌تنهایی مجوز قیمت ایجاد نمی‌کند. مجوز خرید/فروش و گروه خرید/فروش مستقل تنظیم می‌شوند. نام گروه داخلی به کاربر نشان داده نمی‌شود.

## ۷. محصول و قیمت‌گذاری
افزودن محصول:
    /newproduct پرتقال تامسون

گروه خرید مستقیم:
    /newgroup buy|همکار نمونه|direct|1.0|0

گروه فروش ضریبی:
    /newgroup sell|گروه ضریبی|multiplier|1.08|-5000

فرمول گروه ضریبی:
    قیمت نهایی = گرد کردن (قیمت پایه × ضریب) + تعدیل ثابت

گردکردن به نزدیک‌ترین ریال است و قیمت نهایی کمتر از صفر، صفر می‌شود. مبلغ‌ها در نسخه فعلی به ریال هستند.

قیمت پایه:
    /setbase پرتقال تامسون|buy|250000

قیمت مستقیم محصول برای یک گروه مستقیم:
    /setprice پرتقال تامسون|3|260000

شناسه گروه را از خروجی /groups بردارید. گروه ضریبی نباید قیمت مستقیم بگیرد؛ مبلغ هنگام نمایش از قیمت پایه همان محصول و همان جهت محاسبه می‌شود. در نتیجه تغییر قیمت پایه در درخواست بعدی به‌طور خودکار روی گروه‌های ضریبی اثر می‌گذارد.

## ۸. ورود قیمت از Excel
۱. مدیر /template را بزند.
۲. فایل mazandasht_price_template.xlsx را دریافت کند.
۳. نمونه‌ها را حذف یا با داده واقعی جایگزین کند و عنوان ستون‌ها را نگه دارد.
۴. فایل .xlsx را در گفت‌وگوی ربات ارسال کند.
۵. خطاها و پیش‌نمایش را بررسی کند.
۶. فقط در صورت صحت داده‌ها «تأیید و ثبت» را بزند؛ در غیر این صورت «لغو» را انتخاب کند.

ستون‌های لازم: product, side, group, mode, price, factor, fixed_delta.

- قیمت پایه: group و mode خالی، price پر.
- قیمت مستقیم گروه: group پر، mode برابر direct و price پر.
- قیمت ضریبی: group پر، mode برابر multiplier و factor مثبت؛ price می‌تواند خالی باشد.
- side برابر buy/sell است؛ مقدار فارسی خرید/فروش نیز پشتیبانی می‌شود.
- مبلغ‌ها عدد صحیح به ریال هستند.
- گروه با نام و جهت خرید/فروش شناسایی می‌شود.

اگر فایل خطا داشته باشد، ردیف‌های معتبر برای تأیید نمایش داده می‌شوند و خطاها گزارش می‌شوند. پیشنهاد عملی: خطاها را اصلاح کنید و فایل کامل صحیح را دوباره بفرستید تا ورود ناقص ناخواسته رخ ندهد. عملیات ثبت در یک تراکنش دیتابیس انجام می‌شود؛ خطای دیتابیس باید باعث rollback شود.

## ۹. به‌روزرسانی نسخه
پیش از ارتقا از دیتابیس پشتیبان بگیرید. سپس در مسیر پروژه:

    git pull
    docker compose up --build -d
    docker compose ps
    docker compose logs --tail=200 bot

git pull فقط کد را به‌روز می‌کند؛ دیتابیس موجود خودکار migration نمی‌شود. هر تغییر ساختاری باید migration جدید، جدا و بررسی‌شده داشته باشد. فایل migration قبلی را ویرایش یا حذف نکنید. قبل از ارتقای تولید، نسخه را در محیط آزمایشی بررسی کنید.

برای Supabase، migration جدید را از مسیر supabase/migrations طبق روش پروژه اجرا کنید، نتیجه را در SQL Editor یا CLI بررسی کنید و سپس کد ربات را ارتقا دهید.

## ۱۰. پشتیبان‌گیری و بازیابی
پشتیبان منطقی PostgreSQL محلی:
    docker compose exec -T db pg_dump -U mazand -d mazand > backup-mazand.sql

بازیابی به دیتابیس سازگار:
    cat backup-mazand.sql | docker compose exec -T db psql -U mazand -d mazand

فایل پشتیبان شامل اطلاعات کاربران و قیمت‌هاست؛ آن را رمزگذاری کنید و در کانال عمومی Slack قرار ندهید. بازیابی را پیش از اعتماد به نسخه پشتیبان، در محیط آزمایشی امتحان کنید. برای Supabase از قابلیت Backup/Restore موجود در پروژه و پلن استفاده کنید.

## ۱۱. عیب‌یابی
- خطای توکن: مقدار نمونه BOT_TOKEN باقی مانده یا توکن غلط است؛ .env را اصلاح و سرویس را rebuild کنید.
- دیتابیس در دسترس نیست: docker compose ps و docker compose logs db را بررسی کنید؛ URL، نام کاربری و رمز با محیط اجرا همخوان باشند.
- فرمان‌های مدیر جواب نمی‌دهد: شناسه عددی واقعی را در ADMIN_TELEGRAM_IDS قرار دهید و سرویس را بازسازی کنید.
- قیمت نمایش داده نمی‌شود: تأیید حساب، مجوز همان جهت، گروه فعال، قیمت پایه گروه ضریبی و قیمت گروه direct را بررسی کنید.
- Excel رد می‌شود: پسوند xlsx، هفت عنوان ستون، عدد بودن قیمت/ضریب و جهت خرید/فروش را بررسی کنید.
- تغییر schema اعمال نشده: فایل init فقط هنگام ساخت volume اجرا می‌شود. volume را حذف نکنید؛ migration کنترل‌شده اضافه کنید.

## ۱۲. آزمون پذیرش
- کاربر جدید ثبت‌نام کند و پیش از تأیید قیمت نبیند.
- مدیر درخواست را تأیید و مجوزها را مستقل تنظیم کند.
- یک کاربر فقط قیمت خرید و دیگری فقط قیمت فروش ببیند.
- قیمت گروه مستقیم و ضریبی برای یک محصول متفاوت باشد.
- تغییر قیمت پایه روی مبلغ ضریبی اثر بگذارد.
- نام گروه داخلی در پیام کاربر دیده نشود.
- Excel صحیح ثبت و فایل نامعتبر قابل لغو باشد.
- نسخه پشتیبان در محیط آزمایشی بازیابی شود.

## ۱۳. محدودیت‌های نسخه
- اجرای ربات نیازمند پردازه/کانتینر همیشه‌روشن و دسترسی شبکه به Telegram Bot API است.
- فرمان‌های مدیریتی متنی هستند؛ پنل وب و گزارش تاریخی در این نسخه وجود ندارند.
- تاریخچه audit برای تغییرات قیمت ذخیره نمی‌شود.
- پیش‌نمایش Excel در حافظه پردازه است؛ در صورت restart پیش از تأیید، فایل باید دوباره ارسال شود.
- پیش از استفاده تجاری، تست در محیط مقصد، بررسی امنیتی، پشتیبان‌گیری و تنظیم میزبانی لازم است.
